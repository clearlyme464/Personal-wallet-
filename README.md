# Crypto Spending Overview

A tool to import Solana wallet addresses and get an overview of where the money came from and where it went — transaction category breakdown, top counterparties, and a plain-English synopsis generated by Claude.

**Stack:** Next.js (App Router) on Vercel · MongoDB · Helius (Solana transaction data) · Claude API (synopsis generation)

## How it works

1. Paste one or more Solana wallet addresses and click **Add wallet(s)**.
2. The app pulls parsed transaction history for each wallet from Helius's Enhanced Transactions API and stores it in MongoDB.
3. Each wallet page shows total in/out, a category breakdown (swaps, transfers, NFT activity, etc. — by protocol/source), top counterparties, and recent transactions.
4. Click **Generate with Claude** to get a written synopsis of the wallet's spending behavior.
5. The **Portfolio Overview** page combines all tracked wallets into one view with its own synopsis.

## Local setup

```bash
npm install
cp .env.example .env.local   # fill in the three values below
npm run dev
```

Environment variables (`.env.local` locally, or Vercel project env vars in production):

| Variable | Where to get it |
|---|---|
| `MONGODB_URI` | A MongoDB Atlas (or self-hosted) connection string. The app uses the default database in the URI — create one, e.g. `crypto_spending`. |
| `HELIUS_API_KEY` | Free at [dev.helius.xyz](https://dev.helius.xyz) — used to fetch parsed Solana transaction history. |
| `ANTHROPIC_API_KEY` | From [console.anthropic.com](https://console.anthropic.com) — used to generate the spending synopsis. |

## Deploying to Vercel

1. Push this repo to GitHub and import it in Vercel.
2. Add the three environment variables above in the Vercel project settings.
3. Deploy — no other configuration needed.

## Notes

- Only Solana wallets are supported (Helius is Solana-specific). Addresses are validated as base58 Solana pubkeys before being added.
- Sync pulls the most recent 200 transactions per wallet. Click **Re-sync** on a wallet's page to pull the latest activity.
- "Category" in the breakdown is the transaction's protocol/source when Helius identifies one (e.g. `JUPITER`, `MAGIC_EDEN`), falling back to the transaction type (`TRANSFER`, `SWAP`, etc.) otherwise.
- The synopsis is generated from aggregated stats only (totals, categories, counterparties) — no raw transaction data is sent to Claude beyond what's summarized in the prompt.
